    THE DECISION CONTRACT

    Explicit questions. Typed outputs.

    The same schema is sent for every ticket. The expected sample answers are never sent to Laya.

    Four questions, one model call

    choice → department
    A label from Billing, Technical, Sales or Other, with its probability distribution.
    score → urgency
    An expected ordinal value from 0 to 2. The displayed level is the most likely level, not the rounded average.
    noul → cancellation
    The model's estimated probability that the customer expresses intent to cancel.
    choice → requested action
    Information, refund, cancellation, technical help, sales inquiry or an unclear request.

    Our operational policy

    Routing uses department confidence only. Priority follows the urgency score; uncertain priority is flagged for validation. Refunds and cancellations require approval. Other unclear or low-confidence actions need clarification. Cancellation intent adds a retention flag without blocking routing.

    Confidence is a separate model output. It is not measured accuracy. This PoC does not fit temperatures or validate a production threshold.

    A FIVE-MINUTE STORY
    Explain the decision, not just the number.
    Use the live demo to separate model predictions from business responsibility.
    

    

    1 · Start with a routine request
    Choose Routine invoice copy. Read the text, then analyze it. Laya returns four typed signals; no customer reply is generated. The team, priority and action are separate proposals.
    

    2 · Change policy, not the model
    Move from Conservative to Exploratory. The prediction and its inference ID stay the same. Only deterministic rules are recalculated. If routing changes, it is a policy decision, not new model understanding.
    

    3 · A route is not permission
    Use Duplicate charge. A refund prediction requires a person's approval even when routing qualifies automatically. Urgency sets priority; it does not mean the department is unknown.
    

    4 · Challenge the model
    Try The negation test, Not enough context and a new ticket. Inspect the four signals and the policy trace. A confident result can still be wrong; these explanations show our rules, not hidden model reasoning.
    

    5 · Show the trade-off
    Run all 16 examples. Compare automatic routing eligibility and wrong auto-routes across policies. A lower threshold is useful only if the resulting mistakes are acceptable. The visible samples are teaching examples, not a held-out evaluation.
    

    What this demo demonstrates
    • Typed labels, scores and binary signals usable by application code.
    • Several questions handled in one SDK prediction call.
    • Local inference, with separate rules that can change without rerunning the model.
    • Measured latency and exported results for inspection.

    What we have not established: superiority over an LLM, reliable production accuracy, calibrated confidence or financial savings. The keyword baseline is intentionally simple. Local inference still consumes compute and energy. Use an LLM when you need generated explanations or responses; evaluate Laya for bounded decisions with explicit outputs. Production adoption requires representative labels and an independent test set.
